# Multiplayer Bomberman over SSH

## Summary

Build a standalone Go SSH server where players connect with `ssh -p 2323 name@host`, enter a lobby, and play classic 2D Bomberman in 2–4 player rooms.

Target Go 1.27.1, the latest stable release listed in the [official release history](https://go.dev/doc/devel/release). Use [Wish and Bubble Tea](https://github.com/charmbracelet/wish) for SSH sessions and terminal UI, with compatible stable dependencies pinned in `go.mod`.

## Player experience

- Full-screen, colored terminal arena with two-character-wide tiles, distinct player numbers, visible bomb countdowns, explosions, power-ups, scores, and controls. Avoid emoji and custom font requirements; remain readable without color.
- Arrow keys or WASD move; Space places a bomb; Enter confirms lobby actions; Escape leaves a room; Ctrl-C disconnects. Movement uses keypresses and terminal key repeat, with server-enforced movement cooldowns.
- Lobby offers quick join, room creation, and room selection. Rooms hold four players; quick join chooses a waiting room or creates one.
- Players toggle ready. Once at least two players are present and everyone is ready, a three-second countdown starts. Membership changes cancel the countdown.
- Eliminated players watch until the round ends. Show the winner or draw, update room scores, and return everyone to ready-up. Active rooms reject new joins.
- Support terminals of at least 60×24; smaller windows show a resize prompt and suppress gameplay input while the shared match continues.

## Gameplay and implementation

- Use a 15×13 arena with solid borders, indestructible pillars, randomly placed destructible blocks, and cleared corner spawn exits. Generate symmetric maps with routes connecting spawn areas once blocks are destroyed.
- Start with one bomb, blast range two, and a 150 ms movement cooldown. Bombs explode after two seconds; flames last 500 ms. Blasts travel in four directions, stop at solid walls or the first destructible block, and trigger other bombs.
- Players can leave their newly placed bomb but cannot walk back through it. Flames kill instantly, including the owner; simultaneous final deaths produce a draw.
- Destroyed blocks have a 30% chance to reveal an equally weighted bomb-capacity, range, or speed upgrade. Cap capacity at five, range at eight, and speed at a 25 ms cooldown. Reset upgrades each round.
- Last survivor wins. A three-minute round limit produces a draw if multiple players remain. Disconnecting or leaving eliminates that player; existing bombs still detonate.
- Separate deterministic game rules, room coordination, terminal presentation, and SSH hosting. Each room owns its state in a single goroutine running at 20 ticks per second.
- Sessions submit bounded input commands and consume immutable snapshots. Slow connections skip stale frames without blocking matches. Inject time and seeded randomness into game logic for tests.

## Hosting and interfaces

- Provide a `bomber-cli` executable with `--listen` (default `:2323`), `--host-key` (default `./data/ssh_host_ed25519_key`), `--max-sessions` (128), and `--max-rooms` (32).
- Allow connections without signup or passwords. Sanitize SSH usernames for display, disambiguate duplicates, and assign independent internal session IDs.
- Persist an automatically generated SSH host key with restrictive permissions. Require an interactive PTY; reject command execution, file transfer, and forwarding.
- Bound input queues, enforce handshake timeouts, clean up empty rooms, log connection and match events, and shut down gracefully on termination.
- Include build/run instructions, controls, a Docker image, and a Linux systemd example. Document exposing the configured TCP port and persisting the host key.

## Verification and defaults

- Test movement and collisions, bomb limits, blast blocking, chain reactions, power-ups, spawn safety, simultaneous deaths, time limits, and deterministic seeded rounds.
- Test room capacity, ready/countdown transitions, disconnects, rematches, cleanup, and slow-client isolation.
- Exercise multiple real SSH sessions through integration tests, including PTY resize and denied SSH capabilities. Run `go test -race ./...`, `go vet ./...`, and a manual two-terminal match.
- Deliver runnable hosting artifacts and local verification. Public deployment is excluded because no hosting target was supplied.
- Initial scope uses in-memory rooms and scores, with no accounts, database, bots, chat, or reconnection recovery.
